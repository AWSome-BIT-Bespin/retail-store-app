# 구성 설정

## 설정 출처

| 계층 | 위치 |
| --- | --- |
| 애플리케이션 기본값 | `src/{ui,cart,orders}/src/main/resources/application.yml`, `catalog/config/config.go`, `checkout/config/configuration.ts` |
| production profile | `src/{ui,cart,orders}/src/main/resources/application-prod.yml` |
| 로컬 컨테이너 | `src/*/docker-compose.yml` |
| Kubernetes | `src/*/chart/values.yaml`, `src/*/chart/templates/` |
| 이미지 빌드 | `src/*/Dockerfile` |

## 환경변수

| 환경변수 / prefix | 서비스 | 기본값 | 코드 위치 | Helm 출처 |
| --- | --- | --- | --- | --- |
| `PORT` / `port` | Catalog / Checkout / Java 서비스 | 8080 | Catalog config, Checkout `main.ts`, Java `application.yml` | containerPort는 8080 |
| `RETAIL_UI_ENDPOINTS_*` | UI | 빈 문자열 | `EndpointProperties`, `StoreServices` | UI ConfigMap |
| `RETAIL_UI_THEME`, `RETAIL_UI_SEARCH_ENABLED`, `RETAIL_UI_CHAT_*` | UI | theme `default`, search/chat 비활성 | UI 설정 | UI ConfigMap |
| WebSession | UI | 인메모리 세션 | `SecurityConfig` | 별도 Helm 설정 없음 |
| `RETAIL_CATALOG_PERSISTENCE_*`, `RETAIL_CATALOG_SEARCH_*` | Catalog | in-memory, search false | `catalog/config/config.go` | Catalog ConfigMap/Secret |
| `RETAIL_CART_PERSISTENCE_*` | Cart | in-memory | Cart 설정 | Cart ConfigMap |
| `RETAIL_CHECKOUT_PERSISTENCE_*` | Checkout | in-memory | `checkout/config/configuration.ts` | Checkout ConfigMap |
| `RETAIL_CHECKOUT_ENDPOINTS_ORDERS` | Checkout | 빈 문자열, mock Orders | Checkout config/module | Checkout ConfigMap의 조건부 출력 |
| `RETAIL_ORDERS_PERSISTENCE_*`, `RETAIL_ORDERS_MESSAGING_*` | Orders | in-memory | Orders 설정 | Orders ConfigMap/Secret |
| `OTEL_SERVICE_NAME` | Catalog | 미설정 | `catalog/main.go` | chart value 미발견 |

비밀값은 이 문서에 기록하지 않는다. Helm은 provider가 선택된 경우 DB/RabbitMQ 자격 증명을 Secret에서 읽는다.

## Application → Container → Kubernetes 예시

```text
values.yaml: app.endpoints.orders
  → UI ConfigMap: RETAIL_UI_ENDPOINTS_ORDERS
  → UI Deployment envFrom
  → Spring relaxed binding: retail.ui.endpoints.orders
  → StoreServices.ordersService()
  → OrdersClient base URL
```

```text
Orders values: app.persistence.provider = postgres
  → ConfigMap: provider/endpoint/name
  → Secret: username/password
  → Orders Deployment envFrom
  → application.yml retail.orders.persistence.postgres.*
  → DataSourceConfig / Spring Data JDBC
  → Flyway V1/V2 적용 (orders, order_items, shipping_addresses, users)
```

`users` 테이블에는 별도 환경변수나 Secret이 없다. Orders가 PostgreSQL provider로 시작할 때 기존 JDBC 연결과 Flyway 권한을 사용해 `V2__Users.sql`을 적용한다. in-memory provider에서는 Pod 내부 H2에만 생성된다.

## 확인된 구성 불일치

`src/checkout/chart/templates/configmap.yaml`은 `RETAIL_CHECKOUT_ENDPOINTS_ORDERS`를 `app.persistence.provider == redis`일 때만 생성한다. 따라서 기본값인 in-memory에서 `app.endpoints.orders`만 설정해도 Checkout은 endpoint를 받지 못하고 `MockOrdersService`를 사용한다.

## 포트

| 맥락 | UI | Catalog | Cart | Checkout | Orders |
| --- | ---: | ---: | ---: | ---: | ---: |
| 애플리케이션/컨테이너 | 8080 | 8080 | 8080 | 8080 | 8080 |
| Helm Service 기본값 | 80 → 8080 | 80 → 8080 | 80 → 8080 | 80 → 8080 | 80 → 8080 |
| 서비스별 Compose host port | 8888 | 8081 | 8082 | 8085 | 8083 |

각 Compose 파일은 서비스별로 독립되어 있으며, 통합 네트워크나 UI/Checkout endpoint 자동 주입은 제공하지 않는다.
