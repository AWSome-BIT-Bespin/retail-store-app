# 수정 가이드

## Backend API 추가·변경

1. 소유 서비스의 controller/handler와 service/repository 경로를 수정한다.
2. 존재하는 OpenAPI 계약을 수정한다. Catalog·Cart·Orders는 각각 `openapi.yml`을 보유한다.
3. caller의 생성 client와 mapper를 재생성/수정한다.
4. API·통합 테스트를 추가하거나 갱신한다.
5. route가 readiness, ingress, proxy에 영향을 주면 chart Service/Ingress를 점검한다.

| API 소유자 | 시작 파일 | 함께 확인할 consumer |
| --- | --- | --- |
| Catalog | `catalog/controller/controller.go`, `api/catalog.go` | UI Catalog, UI Cart 상품 보강, 주문 관리 상품명 |
| Cart | `cart/web/CartsController.java`, `services/CartService.java` | UI Cart, Checkout 생성 |
| Checkout | `checkout/checkout.controller.ts`, `checkout.service.ts` | UI `KiotaCheckoutService`, Checkout 화면 |
| Orders | `orders/web/OrderController.java`, payload mapper, `OrderService.java` | Checkout `HttpOrdersService`, UI Orders, 주문 관리 |

## API response 수정

다음 순서로 영향을 추적한다.

`API payload/model → 생성 client → UI mapper/service → controller model → Thymeleaf template → 테스트`

Orders item response라면 `orders/web/payload/OrderItem.java`, `OrderItemMapper.java`, `OrderEntity.java`, `ui/client/orders/models/OrderItem.java`, `ui/web/OrderManagementController.java`, `ui/templates/order-management.html`을 함께 확인한다.

## UI 수정

* Route/controller: `src/ui/src/main/java/com/amazon/sample/ui/web/`
* 외부 연동 선택: `ui/config/StoreServices.java`
* 화면: `src/ui/src/main/resources/templates/`
* 공통 layout/navigation: `templates/fragments/layout.html`, `templates/home.html`
* endpoint 없는 로컬 UI는 mock을 쓸 수 있으므로, 실제 backend 연동 검증을 별도로 수행한다.

## DB 변경

| 저장소 | 확인 파일 |
| --- | --- |
| Catalog MySQL | `catalog/repository/`, Catalog MySQL values/templates, Catalog env config |
| Cart DynamoDB | `cart/repositories/dynamo/`, `DynamoDBProperties`, Cart DynamoDB chart |
| Checkout Redis | `checkout/repositories/RedisCheckoutRepository.ts`, config, Redis chart |
| Orders PostgreSQL | `orders/entities/`, repository, `db/migration/`, `DataSourceConfig`, PostgreSQL chart, Testcontainers 테스트 |

Orders DB 변경은 새 Flyway migration으로 추가한다. 배포된 환경에서 `V1__Initial.sql`을 수정하지 않는다.

## 회원가입·로그인·개인 주문 변경

* 사용자 계정: `orders/entities/UserEntity.java`, `UserRepository.java`, `UserService.java`, `UserController.java`, `V2__Users.sql`을 함께 확인한다. 비밀번호는 BCrypt hash만 저장한다.
* API 계약: `orders/openapi.yml` 변경 후 UI의 `kiota:generate@orders`를 실행해 Orders client를 재생성한다.
* UI 세션: `ui/config/SecurityConfig.java`와 `AuthenticationController.java`가 Orders 로그인 검증 결과를 WebSession에 저장한다. 보호 경로를 늘릴 때 기존 공개 Checkout POST의 CSRF·접근 규칙 영향을 확인한다.
* 주문 소유: Checkout에서 로그인 Principal 이메일을 배송지에 설정하고, `OrderManagementController`가 동일한 이메일을 `GET /orders?customerEmail=`에 사용한다.

## 환경변수·endpoint·포트 변경

* 환경변수: 코드 binding/read → 기본값 → Helm ConfigMap/Secret → 필요 시 Compose → unset/set 테스트 순으로 확인한다.
* endpoint: caller 구성, ConfigMap/values, Compose env, 생성 client base URL, 대상 Service DNS와 오류 fallback을 확인한다.
* 포트: application 설정, Dockerfile `EXPOSE`, Compose mapping, Deployment `containerPort`/probe, Service `targetPort`, metrics annotation, Ingress backend를 모두 확인한다.

## Backend 서비스 추가

최소 항목은 서비스 소스·build descriptor·Dockerfile·Compose·Helm chart·health endpoint·테스트, caller API client와 endpoint property, 배포 values의 Service DNS wiring, persistence/messaging/observability 구성이다. 이 저장소에는 확장할 umbrella chart나 CI pipeline이 없다.
